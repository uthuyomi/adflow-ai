# AdFlow AI 料金システム監査・再設計案

このドキュメントは、AdFlow AI の料金体系を変更する前に、現在のクレジット設計、API 原価、利益率、価格上のリスクを整理した調査資料です。

ChatGPT や外部レビュアーへ共有し、料金設計を検討するための判断材料として利用できます。

## 1. 結論

現在の料金体系には、次の重要な問題があります。

- 追加クレジットの単価が月額プランより安く、月額契約を継続する動機を弱めている
- 50,000 credits の追加パックが、同じ 50,000 credits を含む Business プランより 14,800 円安い
- Pro / Business はクレジット量以外の明確な価値差が弱い
- UI に表示されるクレジット消費量と、バックエンドで実際に消費される量が一致していない
- 機能ごとのクレジット数と実際の API 原価に強い相関がない
- API の token 使用量、利用モデル、実原価が保存されていない

リリース初期は、次の構成で運用する方針です。

```text
Free      0 円       500 credits
Starter   2,980 円   2,500 credits
Growth    6,980 円   8,000 credits
Business  問い合わせ
```

通常処理は低原価モデルを利用し、高単価モデルは将来の Deep Analysis など必要な処理だけに明示的に適用します。

---

## 2. 調査前提

現在の実装では、LLM 呼び出しごとの input tokens、output tokens、API 原価を記録していません。そのため、原価は以下の条件で推定しています。

### 標準原価ケース

- Model: `gpt-5.4-mini`
- 1 回の LLM 呼び出し: input 8,000 tokens / output 1,000 tokens
- OpenAI 単価: input $0.75 / 1M tokens、output $4.50 / 1M tokens
- 推定原価: 約 1.68 円 / LLM 呼び出し

### 高原価ケース

- Model: `gpt-5.5`
- 1 回の LLM 呼び出し: input 8,000 tokens / output 1,000 tokens
- OpenAI 単価: input $5.00 / 1M tokens、output $30.00 / 1M tokens
- 推定原価: 約 11.20 円 / LLM 呼び出し

### その他の前提

- 為替: 1 USD = 160 円
- 国内カード決済: Stripe Payments 3.6%
- サブスクリプション: Stripe Billing 0.7% を追加し、合計約 4.3% として試算
- Fly.io、Vercel、Supabase、人件費、サポート費、税金は原価試算に含めない
- X API など、契約プランによって変動する外部 API 費用は別途管理が必要

## 3. 現在の料金体系

### 月額プラン

| Plan | 月額料金 | Monthly credits | 1 credit あたり |
| --- | ---: | ---: | ---: |
| Free | 0 円 | 500 | 0 円 |
| Starter | 4,980 円 | 3,000 | 1.66 円 |
| Pro | 14,800 円 | 12,000 | 1.23 円 |
| Business | 49,800 円 | 50,000 | 1.00 円 |

### 追加クレジット

| Pack | 価格 | Credits | 1 credit あたり |
| --- | ---: | ---: | ---: |
| 1,000 credits | 1,000 円 | 1,000 | 1.00 円 |
| 5,000 credits | 4,500 円 | 5,000 | 0.90 円 |
| 20,000 credits | 16,000 円 | 20,000 | 0.80 円 |
| 50,000 credits | 35,000 円 | 50,000 | 0.70 円 |

### 価格逆転

50,000 credits を取得する場合:

```text
Business plan: 49,800 円
Credit pack:   35,000 円
差額:          14,800 円
```

追加パックは期限なしであるため、大量利用者ほど月額プランを避け、追加パックだけを購入する方が合理的になります。

## 4. 現在のクレジット消費ルール

バックエンドで実際にクレジット消費が接続されている機能は次のとおりです。

| バックエンド機能 | Credits | 処理内容 | モデル呼び出し | 外部 API |
| --- | ---: | --- | --- | --- |
| `workflow_run` | 300 | 旧フルワークフロー | OpenAI 4 回 | 原則なし |
| `pair_analysis` | 80 | 広告・LP ペア分析、AIレビュー | 最大 5 回 | Grok / OpenAI の可能性 |
| `demand_intelligence` | 50 | 需要シグナル収集・分析 | なし | X、YouTube、Google Search、Web 等 |
| `demand_solution_fit` | 120 | 需要クラスタとの適合度評価 | なし | なし |
| `outcome_learning_rebuild` | 20 | 過去成果との学習リンク再構築 | なし | なし |
| `codex_task` | 100 | 承認済み提案からタスク文面生成 | なし | なし |

### 独立機能として存在しない項目

- 競合分析: 独立した課金 API はなく、広告・LP ペア分析や Demand Intelligence に混在している
- ペルソナ分析: 独立した課金 API はなく、Demand Intelligence 内のルールベース出力に含まれる
- 成長学習: 独立名称ではなく、最も近い処理は `outcome_learning_rebuild`

### UI とバックエンドの不一致

| 表示または機能 | UI 表示 | 実際の消費 |
| --- | ---: | ---: |
| Demand scan | 50 | 50 |
| Competitor analysis | 100 | 独立機能なし。近い処理は 80 |
| Ad LP pair analysis | 150 | 80 |
| Full workflow | 300 | 300 |

ユーザーへの説明、残高予測、請求上の信頼性を考えると、この不一致はリリース前に解消する必要があります。

## 5. 機能別の推定原価

| 機能 | Credits | 標準原価 | 高原価 | 補足 |
| --- | ---: | ---: | ---: | --- |
| 需要スキャン | 50 | 約 0〜5 円 | 約 0〜5 円 | LLM 未使用。外部 source 費用は別 |
| 広告・LP ペア分析 | 80 | 約 8 円 | 約 56 円 | OpenAI-only 時は最大 5 回 |
| 競合分析 | 独立機能なし | 算出不可 | 算出不可 | ペア分析等に混在 |
| ペルソナ分析 | 独立機能なし | 約 0〜1 円 | 約 0〜1 円 | ルールベース |
| Solution Fit | 120 | 約 0〜1 円 | 約 0〜1 円 | token overlap による決定論処理 |
| 成長学習 | 20 | 約 0〜1 円 | 約 0〜1 円 | ルールベース |
| Codex Task 生成 | 100 | 約 0〜1 円 | 約 0〜1 円 | 現在はテンプレート生成 |
| フルワークフロー | 300 | 約 7 円 | 約 45 円 | LLM 4 回 |

### 原価設計上の問題

クレジットは API 原価単位として設計されていません。

例えば、ほぼ API 原価が発生しない Solution Fit が 120 credits である一方、最大 5 回のモデル呼び出しが発生する広告・LP ペア分析は 80 credits です。

クレジットを「API 原価」だけで決める必要はありませんが、少なくともユーザーが感じる価値、処理負荷、運営原価の関係を説明できる状態にする必要があります。

## 8. 運営シミュレーション

以下の構成を仮定します。

```text
Free:     60%
Starter:  25%
Pro:      12%
Business:  3%
```

さらに、全ユーザーが毎月クレジットを 100% 消費し、高原価ケース相当の処理を利用すると仮定します。

| ユーザー数 | 月間推定売上 | API 推定原価 | Stripe 費控除後の推定利益 |
| ---: | ---: | ---: | ---: |
| 10 | 45,150 円 | 26,250 円 | 16,959 円 |
| 50 | 225,750 円 | 131,250 円 | 84,793 円 |
| 100 | 451,500 円 | 262,500 円 | 169,586 円 |
| 500 | 2,257,500 円 | 1,312,500 円 | 847,928 円 |
| 1,000 | 4,515,000 円 | 2,625,000 円 | 1,695,855 円 |

この利益には、Fly.io、Vercel、Supabase、監視、メール、サポート、開発、人件費、税金を含んでいません。

現実的には `gpt-5.4-mini` を通常モデルとして使うことで API 原価は大きく下がりますが、初期フェーズでは売上より固定費と運営工数の影響が大きくなります。

## 9. 採用するリリース初期料金プラン

### 推奨構成

| Plan | 推奨月額 | Monthly credits | 対象 |
| --- | ---: | ---: | --- |
| Free | 0 円 | 500 | 主要機能を一通り試す |
| Starter | 2,980 円 | 2,500 | 個人開発者、小規模運用 |
| Growth | 6,980 円 | 8,000 | 継続的な広告改善、A/B テスト |
| Business | 問い合わせ | 個別設計 | チーム、代理店、大量利用 |

### 推奨理由

- 実績ゼロの初期段階では、4つの公開プランは比較負荷が高い
- Pro と Business の違いをクレジット量以外で説明しにくい
- Starter 2,980 円は実績のない初期段階でも試しやすい
- Growth 6,980 円は継続検証へ移行しやすいリリース価格
- Business は seat、サポート、API 同期、利用量が固まってから個別価格にできる

### モデル別の扱い

- 通常分析: `OPENAI_FAST_MODEL` に設定した低原価モデル
- Deep Analysis: `OPENAI_DEEP_MODEL` に設定した高単価モデルを、将来の明示的な機能だけで利用
- 上位モデルをすべてのプランで無制限利用可能にしない

## 11. リスク分析

### 高優先度

- UI と実際のクレジット消費量が一致していない
- 追加パックが月額プランより有利
- モデルごとの API 原価を追跡できない
- `OPENAI_FAST_MODEL` または fallback の `OPENAI_MODEL` が未設定の場合、一部の主要分析が失敗する
- `OPENAI_DEEP_MODEL` は将来の Deep Analysis 用に予約されており、現状の通常処理では利用されない
- 外部 source API の利用量や原価がクレジット設計に反映されていない

### 中優先度

- 実際には独立していない競合分析・ペルソナ分析が、独立商品に見える
- Codex Task 生成など、現在は軽量処理の機能に高いクレジットが設定されている
- クレジット不足、原価超過、不正利用に対する運営アラートが不足している
- Business に seat、権限、サポート、SLA などの明確な価値差がない

## 12. リリース前に必要な計測

料金を最終確定する前に、最低限次の情報を記録する必要があります。

- 実行機能名
- 利用モデル
- provider
- input tokens
- cached input tokens
- output tokens
- reasoning tokens
- 外部 API 呼び出し回数
- 推定 API 原価
- 消費クレジット
- 実行時間
- 成功 / 失敗 / fallback

料金は推定原価だけで決めず、実ユーザーの利用データを 30〜60 日収集して再調整することを推奨します。

## 13. 最終提案

リリース初期の料金体系として、最も適切だと考える構成は次のとおりです。

```text
Free      0 円       500 credits
Starter   2,980 円   2,500 credits
Growth    6,980 円   8,000 credits
Business  問い合わせ
```

同時に、次を実施するべきです。

1. Pro を Growth に統合する
2. Business の固定公開価格を一時的に廃止する
3. 50,000 credits の追加パックを廃止する
4. 追加パックの credit 単価を月額プランより高くする
5. UI とバックエンドのクレジット表示を一致させる
6. 通常モデルと Deep Analysis モデルを分ける
7. 実 token 使用量と原価を保存する
8. 独立機能として存在しない分析名称を整理する

現在の価格水準そのものが極端に高いわけではありません。最大の問題は、プラン間の価値差、追加パックとの価格逆転、クレジットと実原価の不整合です。
